# 文档同步清单

> 目的：项目里的文档、脚本、配置会互相关联（链接、路径、端口、命令），改一处很容易漏掉另一处。
> 本文给出**文档地图**、**联动更新规则**和**自动/人工检查方式**。
> 最后更新：2026-11-11

---

## 1. 文档地图

| 文档 | 谁维护 | 记录什么 | 会被谁引用 |
|---|---|---|---|
| `README.md` | 人 | 项目介绍、架构、构建、运行、目录树 | `AGENTS.md` |
| `AGENTS.md` | 人 + AI | 给 AI 的工作规则、构建细节、目录地图、已知问题 | `README.md` |
| `docs/测试指南.md` | 人 + AI | 测试矩阵、脚本用法、故障注入、UI 手工清单 | `README.md` 目录树、`AGENTS.md` 目录地图 |
| `docs/改造记录.md` | 人 + AI | 改造背景、变更清单、路线、backlog（BL-xx） | `README.md`、`AGENTS.md` 已知问题 |
| `docs/测试指南.md` §9 | 人 + AI | 相关文件表 | — |

| `tools/test/*.ps1` | 人 + AI | 测试脚本 | `docs/测试指南.md` |

## 2. 联动更新规则（改 A 必须看 B）

| 如果你改了… | 必须同时检查/更新… |
|---|---|
| 新增/重命名 `tools/test/*.ps1` | `docs/测试指南.md`（§2 工具表、§9 文件表）、`AGENTS.md` 目录地图、`README.md` 目录树 |
| 新增/重命名 `docs/*.md` | 所有引用它的链接（README/AGENTS/测试指南）、本文档 §1 |
| 改端口（8090/8091/50055/50056/8080/50052/3308/6380） | 对应 `config.ini.example`、`README.md` 架构/运行章节、`docs/测试指南.md` 测试矩阵、`AGENTS.md` 运行约束 |
| 改节点配置结构（`nodes/<节点>/config.ini` 的段落/键） | `config.ini.example`、`README.md` 多节点章节、`AGENTS.md` 第四节、`docs/测试指南.md` L1 检查说明 |
| 改退出码 / 命令行参数（`--config/--logdir`） | `README.md` 运行章节、`AGENTS.md` 第四节、`docs/改造记录.md` |
| 改了健康检查的层级（L0~L4）或级别（PASS/WARN/FAIL） | `docs/测试指南.md` 第 3 节、`docs/测试指南.md` 第 4 节解读表 |
| 关闭/完成 backlog 项（BL-xx） | `docs/改造记录.md` 状态、`AGENTS.md` 第七节已知问题 |
| 新增数据库表/字段 | `server/sql/schema.sql`、`docs/改造记录.md`、测试脚本里的 SQL |

## 3. 自动检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test\doc-sync.ps1
```

检查项：

| 编号 | 检查 | 失败级别 |
|---|---|---|
| D1 | `docs/` 下 md 文件名是否含中文 | WARN |
| D2 | README / AGENTS / docs 里的相对链接目标是否存在 | FAIL |
| D3 | AGENTS 目录地图里的反引号路径是否存在 | WARN |
| D4 | 文档提到的 `tools/test/*.ps1` 是否存在；每个脚本是否被文档提到 | FAIL / WARN |
| D5 | 节点配置里的端口是否在 README 或测试指南出现 | WARN |
| D6 | `docs/文档同步清单.md` 是否存在 | FAIL |

退出码：`0`（无 FAIL）/ `1`（有 FAIL）。

## 4. 人工检查清单（发版 / 大改前过一遍）

- [ ] README 目录树与实际顶层目录一致（`client/ server/ docs/ tools/`）
- [ ] README 的节点端口（8090/8091、50055/50056）与 `nodes/*/config.ini.example` 一致
- [ ] AGENTS 目录地图中每个路径都真实存在
- [ ] 测试指南里每条命令都能直接复制运行（重点看 `tools\test\` 前缀）
- [ ] 改造记录里的 BL 项状态与实际代码一致（已完成/待验收）
- [ ] 文档里没有出现真实密码、Token、邮箱授权码
- [ ] 新增的脚本/文档都已加入对应索引（README 树、AGENTS 地图、测试指南 §9）

## 5. 命名与路径约定

| 类型 | 约定 | 示例 |
|---|---|---|
| 文档 | 中文名，专有名词可保留英文 | `测试指南.md`、`改造记录.md`、`GateServer思维导图.md` |
| 测试脚本 | 英文 kebab-case，按用途分目录 | `tools/test/health-check.ps1` |
| 脚本分类 | 测试相关进 `tools/test/`，其它用途另建目录 | `tools/db/`、`tools/dev/`（预留） |
| 引用方式 | 文档里统一用仓库相对路径 + 反斜杠 | `tools\test\service-run.ps1` |
