### 1.1 代码副本（同一份源码存在于 3 个服务）

数据层是「一次修复、三处拷贝」的形态，规范源固定为 `server/ChatServer/`：

| 文件 | 规范源 | 拷贝 |
|---|---|---|
| `RedisConPool.cc` / `.h` | `server/ChatServer/` | `server/GateServer/`、`server/StatusServer/` |
| `RedisMgr.cc` / `.h` | 同上 | 同上 |
| `MysqlPool.cc` / `.h` | 同上 | 同上 |
| `MysqlDao.cc` / `.h` | 同上 | 同上 |
| `MysqlMgr.cc` / `.h` | 同上 | 同上 |
| `data.h`（`UserInfo` 等结构体） | 同上 | 同上 |
| `const.h`（错误码 / key 前缀 / 消息 ID / 帧长度） | 同上 | 同上 |

> **规范源 = `server/ChatServer/`**。改这 12 个文件必须先改 ChatServer，再同步两份拷贝；
> 2026-11-22 起这 12 个文件已抽到 `server/common/`，服务目录里不应再有副本；`doc-sync.ps1` 的 **D7** 会检查「common 里齐全 + 服务目录无副本 + 三服务都链接 `llfc_common`」。

## 3. 自动检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test\doc-sync.ps1
```

检查项：

| 编号 | 检查 | 失败级别 |
|---|---|---|
| D1 | `docs/` 下 md 文件名是否含中文 | WARN |
| D2 | README / AGENTS / docs 里的相对链接目标是否存在 | FAIL |
| D3 | AGENTS 目录地图里的反引号路径是否存在 | WARN |
| D4 | 文档提到的 `tools/test/*.ps1` 是否存在；每个脚本是否被文档提到 | FAIL / WARN |
| D5 | 节点配置里的端口是否在 README 或测试指南出现 | WARN |
| D6 | `docs/文档同步清单.md` 是否存在 | FAIL |
| D7 | 12 个公共文件是否只在 `server/common/`、服务目录是否无副本、三服务是否都链接 `llfc_common` | FAIL（缺文件 / 有副本 / 未链接） |
| D8 | `message.proto` 是否只在 `server/proto/`、生成物是否只在 `generated/`、四个服务目录是否无副本 | FAIL（缺文件 / 有副本） |
| D9 | README §5 目录树是否列出 `cmake/`、`server/common/`、`server/proto/`；这三个目录是否真实存在 | FAIL（缺条目 / 缺目录） |

退出码：`0`（无 FAIL）/ `1`（有 FAIL）。

## 7. 提交（commit / push）约定 —— AI 不执行，只做总结

> **AI 助手不执行 `git commit`，也不执行 `git push`。**
> 它只负责在提交前**总结本次工作内容**（供人写 commit message），
> 真正暂存、提交、推送由用户自己完成。

| 谁 | 做什么 |
|---|---|
| **AI** | 改代码 / 改文档；跑构建与测试；**提交前给出总结**：改了哪些文件、为什么改、怎么验证、还剩什么 |
| **AI 不做** | `git commit`、`git push`、`git reset --hard`、`git rebase` 等会写历史或改动远端的操作 |
| **用户** | 在 VSCode 的「暂存更改 / Staged Changes」里审阅 → 自己填 commit message → 自己 commit / push |

提交前总结的固定格式（AI 每次交付时给出）：

1. **改了什么**：按模块列文件（`client/` / `server/` / `docs/` / `tools/`）
2. **为什么**：对应的问题、需求或 backlog 编号（如 BL-15 / BL-17）
3. **怎么验证**：构建结果、跑过哪些测试（`health-check` / `api-test` / `doc-sync` 的汇总行）
4. **剩余风险与待办**：暂缓项、已知限制（指向 `改造记录` 的 BL 表）

> 即使 AI 判断「改动可以提交了」，也只能到这里为止——**最后一步必须由用户按下去**。
> 需要 AI 提供命令时，它只输出 `git` 命令示例，不代替执行。
